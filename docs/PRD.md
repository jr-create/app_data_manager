# PRD：软件数据全览与迁移清理工具（Software Data Migrator）

| 项目信息 | 内容 |
| --- | --- |
| 文档语言 | 中文 |
| 项目名称 | `software_data_migrator` |
| 技术形态 | Python 3.13 + PySide6 桌面 GUI（Qt 6） |
| 目标平台 | Windows 10 / Windows 11（优先），代码结构预留跨平台扩展位 |
| 运行方式 | 本机运行的桌面应用，需要普通权限即可扫描，卸载/删除系统级目录时申请管理员权限 |
| 文档版本 | v1.0（简单 PRD） |

## 1. 原始需求复述（用户原文）

> "现在电脑上软件，许多内容都会直接放在C盘中，普通用户无法查看，我需要保证在更换电脑的时候，能够保证知道、备份和删除各种软件所有存储内容，所以需要你开发一个软件，能够获取电脑所有安装的软件，并且软件存储的所有路径和大概内容。能够支持备份和删除。"

**已确认约束（不再变更）**

- 技术形态：Python 3.13 + PySide6，Windows 优先。
- 功能范围固定为五段式：**扫描已安装软件 → 展示每个软件的所有数据存储路径及占用大小/内容类型 → 备份（打包）→ 数据删除（残留清理）→ 调用官方卸载程序**。
- 本 PRD 不含竞品/市场分析。

## 2. 产品定义

### 2.1 问题本质

用户的核心场景是**换机**，而非日常磁盘清理。换机带来三个刚性诉求：

1. **可见**：普通用户不知道软件把数据写到了 C 盘的哪些角落（`%APPDATA%`、`%LOCALAPPDATA%`、`%PROGRAMDATA%`、`%USERPROFILE%` 下的隐藏 `.xxx` 配置目录等）。
2. **可带走**：换机前要把这些散落的数据完整打包备份，避免"软件重装了但配置和历史数据没了"。
3. **可彻底清除**：旧机器上要把软件及其残留删干净，不留孤儿目录、不留隐私数据。

因此产品的价值主张是：**把"软件 → 它写在哪 → 占多大 → 怎么备份 → 怎么删干净"这条链路可视化、可操作、可回溯，并且全程安全可控。**

### 2.2 产品目标（Product Goals）

| 编号 | 目标 | 说明 | 衡量指标 |
| --- | --- | --- | --- |
| G1 | **全量可见** | 一次扫描，把所有已安装软件（含 Win32、MSIX/Store、用户级安装）及其在磁盘上的全部数据存储路径、占用大小、内容类型完整呈现 | 扫描覆盖率：注册表卸载项中 100% 读取；用户数据根目录下 ≥90% 目录完成软件归属（其余明确归入"未识别"） |
| G2 | **迁移可带走** | 支持按软件/多选批量，把关联数据打包为可迁移的备份归档，并生成可人读的清单 | 备份成功率 100%（被占用文件给出明确跳过清单，不静默失败）；备份产物可被本工具或系统解压工具打开 |
| G3 | **删除可放心** | 卸载 + 残留清理 + 删除全链路具备多重安全保护，绝不误删系统目录 | 系统黑名单目录命中率拦截 100%；任何删除操作前必有二次确认；可回滚（回收站/备份优先） |

三个目标正交：G1 解决"知道"，G2 解决"带走"，G3 解决"删除"，互不重叠，覆盖用户换机全流程。

### 2.3 用户故事（User Stories）

| 编号 | 用户故事 | 验收要点 |
| --- | --- | --- |

### 3.2 路径 → 软件 归属推断规则（核心难点）

推断按优先级逐级执行，**命中即停**；全部未命中则归入"未识别（Orphan）"分组。

| 级别 | 规则 | 说明 | 示例 |
| --- | --- | --- | --- |
| L1 精确名匹配 | 目录名（归一化后）== 软件 DisplayName（归一化后） | 归一化：转小写、去空格/下划线/连字符、去版本号与括号内容、去 Inc./Ltd./Corp. 等后缀 | `Google Chrome` ↔ `Chrome` |
| L2 发布商匹配 | 目录名 == Publisher（归一化）；或目录名包含 Publisher 主键词 | 利用注册表 Publisher 字段 | Publisher=`Microsoft Corporation` ↔ `Microsoft` |
| L3 安装路径反查 | 目录名与 `InstallLocation` 末级目录名一致；或该目录位于 InstallLocation 之下 | 强证据，置信度高 | InstallLocation=`...\Programs\Notepad++` ↔ `%LOCALAPPDATA%\Programs\Notepad++` |
| L4 可执行文件/进程名匹配 | 目录名 == 主 exe 名（去 `.exe`）或 PackageFamilyName 主键词 | 覆盖 MSIX | `ms-teams` ↔ PackageFamilyName 含 `MSTeams` |
| L5 模糊/归一化匹配（含阈值） | 归一化后的目录名与软件名互为子串，或编辑距离相似度 ≥ 阈值（建议 0.75，可在设置中调整） | 需向用户展示相似度分数与置信度标签 | `vscode` ↔ `Visual Studio Code`（需别名表） |
| L6 内置别名表兜底 | 维护常见软件"显示名 ↔ 常见目录名"映射表（数据文件，可随版本更新） | 解决 L5 无法覆盖的知名软件 | `Visual Studio Code` → `Code`；`JetBrains PyCharm` → `PyCharm2023.1`；`Node.js` → `npm`/`nodejs` |
| LX 未识别 | 以上均未命中 | 归入"未识别"分组，UI 单独列表展示，**允许手动指派**（P1-4） | — |

**归属推断验收标准**

1. **覆盖率**：对一台装有 ≥30 个常见软件的标准机器，`%APPDATA%`/`%LOCALAPPDATA%` 第一层目录中，归属准确率（人工抽检 20 个样本）须 ≥85%；其余必须明确进入"未识别"分组，**不允许强行归属**。
2. **可解释**：每个归属结果必须在 UI 上展示**匹配级别（L1~L6）与置信度分数**，并对 L5 模糊匹配显式标注"模糊匹配，请确认"。
3. **可纠正**：任何归属结果支持用户手动改判（P1-4），改判后本地持久化。
4. **无跨软件误吞**：一个目录最多归属给一个软件；若多个软件竞争同一目录，取置信度最高者并在 UI 标注"存在冲突"。
5. **性能**：全部软件（按 300 个计）对全部候选目录（按 2000 个计）的归属推断，须在 3 秒内完成（纯字符串运算，不涉及磁盘 I/O）。

### 3.3 内容类型判定规则（P0-5 支撑）

按路径关键字与位置判定类型标签，顺序匹配，命中即停：

| 类型 | 判定规则（示例） |
| --- | --- |
| 缓存 Cache | 路径含 `Cache`、`Caches`、`CacheStorage`、`Code Cache`、`GPUCache`、`Temp`、`tmp` |
| 日志 Log | 路径含 `Log`、`Logs`；或文件扩展名为 `.log`、`.etl` |
| 插件 Plugin | 路径含 `Plugins`、`Extensions`、`Addons`、`Add-ins` |
| 配置 Config | 路径含 `Config`、`Settings`、`Preferences`；或位于 `%APPDATA%` 且文件扩展名为 `.json`/`.ini`/`.xml`/`.cfg`/`.toml`/`.yaml`；或为 `%USERPROFILE%` 下的 `.xxx` 点文件/点目录 |
| 数据 Data | 路径含 `Data`、`Databases`、`db`、`Storage`、`Local Storage`、`Session Storage`；或位于 `%USERPROFILE%\Documents`、`%PUBLIC%\Documents` |
| 其他 Other | 以上均未命中 |

- 左侧主区（约占 65%）：软件列表（QTableWidget / QTreeView），首列为多选复选框；列：图标、软件名、发布商、版本、总占用、关联路径数；支持列头点击排序。
- 右侧详情面板（约占 35%）：选中软件的关联路径明细（QTreeWidget 按类型分组），每行显示：类型标签、路径、占用大小、文件数、最后修改时间；底部操作按钮：在资源管理器中打开、移除归属（P1-4）。
- 底部操作栏：已选统计（项数 + 合计大小）+ 批量备份 / 批量删除 / 调用卸载 / 导出 CSV / 导出 JSON。
- 状态栏：扫描状态、统计信息、进度条。

## 5. 关键非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 注册表/MSIX 扫描 < 3s；300 软件 × 2000 候选目录的归属推断 < 3s；占用大小计算后台异步，不阻塞 UI；结果缓存，二次打开秒显 |
| 安全 | 系统关键目录硬黑名单；删除三重确认（路径清单 + 输入 DELETE + MessageBox）；默认"先备份/回收站"策略；管理员权限显式提示 |
| 稳定性 | 单个软件解析/扫描失败不影响整体；所有文件操作捕获 `PermissionError`/`FileNotFoundError` 并汇总为报告；绝不静默失败 |
| 兼容 | Windows 10 21H2+ / Windows 11；Python 3.13；正确处理长路径（>260 字符，启用 `\\?\` 前缀）、非 ASCII 路径（中文用户名） |
| 可维护 | 扫描 / 归属推断 / 备份 / 删除 / 卸载 五个模块解耦，便于架构师分层设计 |

## 6. 验收标准（全局 DoD）

1. 在一台装有 ≥30 个软件的 Windows 机器上，一次扫描可列出 ≥95% 的已安装软件（注册表 + MSIX）。
2. 每个软件可展示其 ≥1 条真实存在的关联数据路径，并显示正确的占用大小与类型标签。
3. 归属推断准确率（人工抽检 20 个样本）≥85%，未覆盖项明确进入"未识别"分组。
4. 多选 3 个软件批量备份，成功产出 zip + manifest.json，且解压后目录结构与原路径一致。
5. 执行一次删除：黑名单目录被自动拦截、二次确认齐全、删除后目标路径确实移除（或进入回收站）。
6. 执行一次卸载：正确从注册表读取 UninstallString 并执行，MSIX 走 `Remove-AppxPackage`，卸载后能扫描出残留。
7. 大小计算过程中 UI 可正常交互（可滚动、可切换选中项），进度条持续更新。
8. 导出 CSV/JSON 字段完整，可被 Excel / JSON 解析器正常打开。

## 7. 待确认问题（Open Questions）

| # | 问题 | 影响 | 建议默认值 |
| --- | --- | --- | --- |
| Q1 | 备份归档格式：zip（兼容性好，无压缩级别控制粒度）还是 7z（压缩率高，需额外依赖）？ | 影响备份体积与依赖 | 建议 **zip**（Python 标准库原生，用户可直接解压） |
| Q2 | 备份默认路径与内容范围：是否默认**排除缓存与日志**类路径（体积大但迁移价值低）？ | 影响备份大小与耗时 | 建议默认排除 Cache/Log，UI 提供开关让用户自行包含 |
| Q3 | MSIX 应用是否默认扫描 `-AllUsers`（需管理员权限，可能显著变慢）？ | 权限与性能 | 建议当前用户优先，提供"包含所有用户"开关（需管理员） |
| Q4 | 占用大小计算深度：是**首次全量计算**（慢但数据完整）还是**懒加载**（选中才算，快但初始无大小）？ | 首屏体验 | 建议：目录枚举后先快速展示，大小计算后台全量跑，UI 逐个填充（渐进式） |
| Q5 | 删除策略默认项：回收站 vs 先备份后删除？ | 安全性与磁盘占用 | 建议默认"先备份后删除"（与换机场景一致），设置中可切换 |
| Q6 | 是否需要**还原/导入**功能（在新机器上恢复备份）？ | 决定是否为 P1 还是出 MVP 后延后 | 用户场景是换机，建议列为 **P1**（P1-2），MVP 先保证能备份 |
| Q7 | 是否需要在 MVP 中支持**卸载后注册表残留清理**？ | 风险等级高 | 建议 **P2**，默认关闭，专家模式才开放 |
| Q8 | 单文件 exe 打包（PyInstaller）是否在本次范围内？ | 分发方式 | 建议 MVP 阶段提供源码 + 运行脚本；打包列为 P1 |
| Q9 | 界面语言：仅中文还是中英双语？ | 开发量 | 建议 MVP 仅中文（用户为中文用户） |
| Q10 | 是否需要处理**被占用文件**（如正在运行的软件锁定了数据文件）？ | 备份完整性 | 建议：跳过 + 明确报告清单（不静默失败），P0-8 已定义 |
